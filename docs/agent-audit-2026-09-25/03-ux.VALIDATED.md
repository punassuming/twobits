## High-Priority Claims Verification

### 1. Shelf Snap Vision Analysis
**Audit claim:** "Shelf Snap claims 'local processing when possible' but vision analysis is 100% cloud."

**Finding:** ❌ FALSE

**Evidence:**
- **LocalVisionService exists and is wired:** `/home/user/twobits/apps/shelf-snap/app/src/main/java/com/shelfsnap/app/data/local/LocalVisionService.kt` exists and uses LiteRT-LM (Gemma 4 E2B/E4B) for on-device vision analysis.
- **Integrated into ItemRepository:** In `ItemRepository.kt` lines 113-159, the `analysePhotos()` function has three execution modes:
  - `ExecutionMode.LOCAL` (lines 138-151): Uses `localVisionService.analyse()` with on-device LiteRT-LM model
  - `ExecutionMode.PRO` (lines 128-137): Uses cloud vision via worker backend
  - `ExecutionMode.BYOK` (line 152): Uses user's OpenAI API key
- **Onboarding copy is accurate:** The onboarding privacy screen says "When you're ready for AI features, add your own key or Pro in Settings — it's optional." It does NOT claim "local processing when possible." The actual text is accurate (inventory stays on device, AI is optional).

**Conclusion:** Shelf Snap's vision analysis is HYBRID, not 100% cloud. Users can choose LOCAL, PRO, or BYOK modes in Settings → AI configuration. The onboarding copy correctly positions the app as local-first and optional.

### 2. Scrybe Privacy Disclosure & Local vs Cloud Distinction
**Audit claim:** "Scrybe has no privacy disclosure; doesn't distinguish local Whisper from cloud transcription."

**Finding:** ⚠️ PARTIALLY CORRECT (needs refinement)

**Evidence:**
- **Onboarding has NO privacy disclosure:** OnboardingScreen.kt shows only:
  - Mic permission request ("Required to record audio")
  - Optional API key entry ("Stored encrypted on this device only")
  - No explanation of local vs cloud modes or data flows
- **Settings DO distinguish local vs cloud:** AIConfigScreen.kt (lines 277-336) shows:
  - `AiSourceSegment` lets users choose between LOCAL, BYOK, and PRO modes
  - LOCAL mode (lines 310-319) uses `LocalModelPicker` for Whisper models (downloaded on-device)
  - BYOK/PRO modes (lines 291-308) use OpenAI's cloud transcription service
  - Spoken language field is hidden when LOCAL is selected, confirming different pipelines

**Conclusion:** The audit is CORRECT that onboarding lacks privacy disclosure and local/cloud explanation. However, the Settings screen DOES provide this distinction. Users must discover it themselves in Settings → AI configuration → Transcription.

### Corrected Findings for Engineering Priorities

#### 1. Shelf Snap Vision is NOT "100% Cloud"
**Accurate statement:** Shelf Snap supports three vision analysis modes:
- **LOCAL:** On-device LiteRT-LM (Gemma 4 E2B/E4B)
- **BYOK:** User's own OpenAI API key
- **PRO:** Managed cloud via worker backend

Users select the mode in Settings → AI configuration → Transcription/Vision. The onboarding correctly positions the app as local-first (inventory stays on device) with optional AI features.

**Priority Action:** Clarify in documentation that Shelf Snap DOES support on-device vision analysis via downloaded Gemma models. The "100% cloud" claim was incorrect.

---

#### 2. Scrybe: Onboarding Lacks Privacy Disclosure, But Settings Provides LOCAL/CLOUD Choice
**Accurate statement:** 
- Onboarding provides NO explanation of local Whisper vs cloud transcription pipelines
- Settings → AI configuration → Transcription DOES provide LOCAL/BYOK/PRO source selection
- Users can download local Whisper models and switch between modes

**Priority Action:** Add a privacy/data flow screen to Scrybe's onboarding (after "Quick setup" step) explaining:
  - Local transcription: Whisper runs on-device (optional download)
  - Cloud transcription: Uses OpenAI API (requires key)
  - Transforms/insights: Similarly support LOCAL/BYOK/PRO modes

**Priority Action:** No change needed. Success feedback already exists via snackbar + listing URL tracking.

**Priority Action:** TaskInbox empty state should add link: "Extract tasks from a recording" (navigation to SessionDetail or recording modes).
