## 1. Primary User Journeys

### Scrybe: Record → Transcribe → Transform → Organize
**Path:** CaptureScreen → SessionDetailScreen → Profiles/Tasks

- **Record:** CaptureScreen (apps/scrybe/feature/capture/src/main/kotlin/dev/scrybe/feature/capture/CaptureScreen.kt) is the main hub; shows waveform, elapsed time, mic level feedback.
  - User can start/pause recording (phase management at line 107-126 CaptureViewModel.kt)
  - Auto-transcription can trigger after stop if enabled (line 150-151)
  - Issue: Unclear if recording silently fails — only error in uiState.errorMessage; no prominent error dialog shown initially
- **Transcribe:** Handled by RecordingForegroundService, transitions to transcribing notification (RecordingNotificationFactory.kt line 79-99)
  - Auto-transcribe shown as toast notification in app (TranscriptionProgressViewModel)
  - User can see progress in ProgressFooter (now standardized via PR #161)
- **Transform:** SessionDetailScreen (apps/scrybe/feature/session-detail/src/main/kotlin/dev/scrybe/feature/sessiondetail/SessionDetailScreen.kt) allows applying profiles (AI transforms)
  - Profiles can generate summaries, extract tasks, rename sessions
  - User journey stops here — no clear next step after transform (no export, no multi-app sharing)
- **Organize:** Can folder sessions, star favorites, but no dead-end handling for empty folders

### Shelf Snap: Photo → Analysis → Listing → Cross-List
**Path:** CameraScreen → ItemDetailScreen → ListingSummaryScreen

- **Photo capture:** CameraScreen (apps/shelf-snap/app/src/main/java/com/shelfsnap/app/ui/camera/CameraViewModel.kt) lets users snap, tap to analyze
  - User sees spinning indicator while analysis runs
  - Issue: Analysis errors shown in Snackbar (line 146 CameraViewModel.kt), but no pre-check for missing API key/auth before wasting time on photo
- **Analysis:** Vision API call maps errors to friendly messages (VisionAnalysisService.kt line 368-400)
  - Errors are specific: "Invalid or missing OpenAI API key" vs. "Rate limited" vs. "Timeout"
  - Good: Error messages guide user to Settings for fixes
- **Draft listing:** ItemDetailScreen (ItemDetailViewModel.kt) fills title/description/price from analysis
  - Market research can be kicked off (researchPrice() at line 160)
  - Issue: If research fails with network error, error shown in Snackbar, but user is left staring at partial data — no retry button in the snackbar
- **Cross-list:** ListingSummaryScreen (line 64) shows Shopify/eBay listings
  - Issue: No success confirmation or "view live listing" link — user doesn't know if cross-listing actually worked

### Price Drop: Search/Scan → Track → Alert → Research
**Path:** SearchScreen or BarcodeScanScreen → ProductDetailScreen → WatchScreen

- **Search/Scan:** SearchScreen or BarcodeScanScreen capture product
  - Scan is slow if offline (no graceful degradation message)
  - Issue: No inline feedback that product is being looked up
- **Track:** ProductDetailScreen shows price history chart (uses Vico for charting)
  - User sets target price via dialog (line 98-99)
  - Current/target price shown clearly
- **Alert:** WatchScreen shows all tracked products in tabs (line 148 WatchScreen.kt uses AppEmptyState for "no items")
  - Notifications should fire when price drops below target (mechanism not traced in detail)
- **Research:** AskScreen (apps/price-drop/app/src/main/kotlin/com/twobits/pricedrop/ui/ask/AskScreen.kt) lets user ask AI questions
  - Issue: Journey from ProductDetail → Ask is not obvious; Ask is a separate nav tab, not linked from product

## 2. Error Messaging

### Consistency: **MIXED — improving**

**Shelf Snap (best practice):** VisionAnalysisService.kt lines 368-400 maps HTTP codes and exceptions to 8 friendly messages:
```
ERROR_INVALID_KEY = "Invalid or missing OpenAI API key. Check Settings."
ERROR_RATE_LIMITED = "Rate limited by OpenAI. Wait a moment and try again."
ERROR_TIMEOUT = "Analysis timed out. Check your connection and try again."
ERROR_NETWORK = "Network error. Check your connection and try again."
ERROR_UNKNOWN = "Something went wrong. Please try again."
```
- Actionable: tells user what to do next (check settings, check connection, wait)
- Tests verify the mappings (VisionAnalysisErrorTest.kt)

**Scrybe:** Uses generic "Failed to X" patterns:
```
"Failed to start recording" (RecordingForegroundService.kt line 212)
"Failed to save recording" (line 348)
"Failed to suggest a profile" (ProfilesViewModel.kt line 285)
```
- Not actionable: doesn't explain *why* it failed or what to do
- Same message for network error, permission error, disk full — user can't distinguish

**Price Drop:** Most errors are inline validation (missing API key shows at screen level in SettingsScreen), not shown as transient errors
- When errors do occur, they go to Snackbar (ProductDetailScreen.kt line 104)
- No specific error message mapping for network failures

### Display pattern: **CONSISTENT across all 3 apps**
- **Snackbar** is the standard (SnackbarHostState in ItemDetailScreen, ProductDetailScreen, etc.)
- AlertDialog is used only for confirmations (delete, discard) — good, not for errors
- No Toast usage — good
- Issue: Snackbar auto-dismisses after 4-5s; users might miss error if screen is busy

## 3. Loading & Progress Feedback

### ProgressFooter: Successfully standardized (PR #161)
All 3 apps now show progress in a unified footer (shared/design/ProgressFooter.kt):
- `ProgressFooter(visible, primaryText, secondaryText, tertiaryText, progressFraction, startedAtMs, onCancel)`
- Shared implementation eliminates the 3 prior per-app "Toast" variants
- Ticking elapsed time automatically managed (line 104-112 ProgressFooter.kt)
- Clickable for detail view (e.g. Shelf Snap's market research progress on ItemDetail)

**Used by:**
- Scrybe: Recording + auto-transcription (apps/scrybe/app/src/main/kotlin/dev/scrybe/android/ui/ScrybeApp.kt line 166)
- Shelf Snap: Local analysis + market research (apps/shelf-snap/app/src/main/java/com/shelfsnap/app/ui/navigation/AppNavigation.kt lines 105, 115)
- Price Drop: Watchlist refresh (line 116, 123 AppNavigation.kt)

### Other loading indicators: **INCONSISTENT**
- CircularProgressIndicator at screen center (ProductDetailScreen.kt line 134, CameraViewModel during analysis) — fine
- Spinning icon button in TopAppBar (ProductDetailScreen.kt line 120-124) — harder to notice than ProgressFooter
- Issue: Some screens show button spinner for refresh action but ProgressFooter separately for background task — visual redundancy

**No skeleton screens used.** Screens show empty state briefly before data loads — better than skeleton, but spinners would reduce perceived latency.

## 4. Empty States

### StandardEmptyState: AppEmptyState component (shared/design/EmptyState.kt)
All 3 apps import and use it consistently (centering, icon, title, subtitle, optional actions).

**Scrybe:**
- TaskInboxScreen (line 159): "No tasks yet" with no action
- Issue: User doesn't know how to create tasks — no "Create task" link

**Shelf Snap:**
- InventoryScreen (lines 214-234): Three empty states
  - Search with no results → shows "no items match search" (no action, OK)
  - Filter with no results → shows "Show all items" button (good!)
  - True empty → shows InventoryWalkthrough with 3 illustrated steps + "Snap first item" button (excellent!)
    - Walkthrough explains: Photo → AI analysis → draft listing (InventoryScreen.kt lines 258-326)
- ListingSummaryScreen (line 134): "No listings created yet" (no action)

**Price Drop:**
- WatchScreen (line 148): Two empty states
  - "You're not watching anything yet" when no products tracked
  - After search with no results: "No products found" (no action to retry search)
- Issue: "No products found" doesn't offer "Try different search" or link back to search screen

### Summary:
- **Shelf Snap is best**: InventoryWalkthrough gives 3 illustrated steps for brand-new user
- **Scrybe middle**: TaskInbox is empty but doesn't explain how to populate
- **Price Drop weak**: Empty search results is a dead end

## 5. Offline Handling

### Network connectivity checks: **ABSENT**
No `ConnectivityManager` or modern network callback patterns found in any app.

### Error mapping for offline scenarios: **PARTIAL**
- **Shelf Snap** maps IOException → "Network error. Check your connection and try again." (VisionAnalysisService.kt line 376-377)
  - Good: user knows to check WiFi/data, but doesn't know if they're online
- **Scrybe** has generic "Failed to X" — doesn't distinguish network errors from other failures
- **Price Drop** doesn't surface network errors prominently; assumes connection or fails silently

### Offline first:
- **No offline-first flow** in any app — all require cloud connectivity for core features
  - Scrybe: transcription (unless using local Whisper model, which is device-only)
  - Shelf Snap: vision analysis + market research (both cloud)
  - Price Drop: product search + price history (API-backed)
- **No cached data shown** when offline
- **No queue/retry pattern** for failed requests — user must manually retry

### Dead end: user attempts cloud action while offline
- Shelf Snap analysis fails → Snackbar shows "Network error" → user taps retry, but retries forever with no backoff
- Price Drop search hangs for 30s then fails with generic error
- Scrybe doesn't handle transcription service being unreachable gracefully

## 7. Notifications

### Scrybe: Recording + Transcribing
**RecordingNotificationFactory.kt (lines 20-100):**
- Single channel: `CHANNEL_ID = "recording_channel"` with `IMPORTANCE_LOW` (line 22-26)
- Recording notification: "Recording in progress · MM:SS · [Input level]" + Stop action (line 60-69)
- Transcribing notification: "Transcribing… Turning your recording into text" (line 79-99)
- Issue: Same channel for both phases — user might not realize status changed

**Scrybe Settings:**
- User can configure "Channels" (multi-channel recording) in SettingsScreen.kt (line 289-298)
- But this is audio channels (mono/stereo), not notification channels

### Shelf Snap: No background task notifications
- Local analysis + market research use ProgressFooter in UI (no notification)
- Issue: If user navigates away during analysis, no notification badge or ongoing notification to remind them work is happening

### Price Drop: No price-alert notifications found
- Watchlist exists but mechanism for triggering alerts not visible in code audit
- Likely uses JobScheduler or WorkManager (not traced)

### Summary:
- **Only Scrybe has visible notifications** — and they're well-designed (ongoing, specific, actionable Stop button)
- **Shelf Snap/Price Drop lack background task feedback** — user might not know their work is being processed if they leave

## 8. Onboarding

### Scrybe (4 screens, ~5 min read)
1. **Welcome:** "Record your thoughts" + icon, big CTA to continue
2. **Pick mode:** MEETING / IDEA / TASKS / JOURNAL, with descriptions ("Action items + summary" etc.)
   - Issue: **No privacy/data disclosure** — doesn't explain that API key is for cloud transcription
   - Issue: Doesn't explain which modes are local vs. cloud
3. **Quick setup:** Request mic permission + optional "add your API key"
   - Good: Optional API key means user can try local mode first
   - Issue: Doesn't explain the difference in capability (local Whisper vs. cloud)
4. **Pipelines:** Shows 2 example workflows (Meeting notes, Daily journal) with install counts
   - Vague: "community-built workflows" — doesn't explain what they do or cost

**Missing:** No explanation of local vs. cloud processing; no privacy statement; no data retention info.

### Shelf Snap (4 screens, ~5 min read)
1. **Capture:** Camera icon, "Snap photos of items you want to sell"
2. **AI Analysis:** Sparkle icon, "Automatic item details and pricing"
   - Issue: Doesn't mention vision API or cost
3. **Sell:** Sell icon, "Cross-list across multiple platforms"
   - Issue: Doesn't mention which platforms (Shopify? eBay? Etsy?)
4. **Privacy:** Lock icon, "Your data is private. Local processing when possible."
   - Good: Acknowledges privacy concern
   - Issue: Doesn't explain what "local processing" means (photos stay on device? Metadata sent?) or what's NOT local (vision API is 100% cloud)

**Missing:** No cost model; no API/auth setup guidance; no explaining why API key is needed.

### Price Drop (3 screens, ~3 min read)
1. **Never overpay:** Price tracking + alerts concept
2. **Your privacy first:** "Price checks run through our secure proxy. Your API keys never leave your device. No account required."
   - Best in class: Specific, actionable, mentions key protection
3. **AI-powered research:** "Ask our AI to find deals, look up price history, or discover coupons"

**Missing:** Doesn't explain which APIs they need (OpenAI, Anthropic, web search service).

### Summary:
- **Price Drop is best**: Explicitly mentions privacy, proxy, no account required
- **Shelf Snap middle**: Mentions privacy but vague on what's local vs. cloud
- **Scrybe weakest**: No privacy disclosure at all; local vs. cloud modes not explained

## Top 5 Priorities

1. **Disambiguate local vs. cloud processing in onboarding + settings**
   - Scrybe: Which recording modes use local Whisper vs. cloud transcription?
   - Shelf Snap: Vision analysis is 100% cloud — don't claim "local processing when possible"
   - Action: Add a "Privacy" screen in onboarding (like Price Drop) + link to docs explaining each feature's data flow

2. **Add network-aware error handling + offline messaging**
   - All apps: Show "Check your internet connection" if network is down, not just "Network error"
   - Add retry buttons to Snackbars for retryable errors
   - Shelf Snap CameraScreen: Check for API key + network before spending time on photo analysis
   - Action: Implement ConnectivityManager listener; add "Retry" action to error Snackbars

3. **Unify error messages to be actionable across all apps**
   - Scrybe: Stop generic "Failed to X" messages; map errors like Shelf Snap does
   - Add testable error-mapping (like VisionAnalysisErrorTest.kt) to all apps
   - Action: Create shared error-message constants in shared/model or shared/ui; add ViewModel tests

4. **Complete empty-state journeys with next steps**
   - Scrybe TaskInbox: Add "Create task" CTA
   - Price Drop search: Add "Try different search" or "View all products" CTA
   - Action: Audit each empty state in figma; add missing CTAs; test the flow end-to-end

5. **Improve accessibility coverage for icon-heavy screens**
   - Add contentDescription to all visual-only controls (waveform, level indicators, chart)
   - Implement semantics for complex custom composables (recording level meter, price chart)
   - Action: Run accessibility audit in Android Studio; aim for 90%+ contentDescription coverage; add a11y tests
